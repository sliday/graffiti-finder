# clean-krakow — Privacy & data flow

What runs locally, what leaves the machine, and who can see what. Written
in response to the question "everything is done locally, correct?" — short
answer: yes for the decision-making, no for the imagery source.

---

## Runs entirely on your machine

| Component | Where |
|---|---|
| SAM3 vision inference | MLX on Apple Silicon (Python 3.13 sidecar in `vendor/mlx_sam3`) |
| CLIP zero-shot classifier | torch + MPS in the main 3.12 env |
| Geometric filters (area, aspect, std) | Python on CPU |
| pHash dedup | local `imagehash` library |
| SQLite queue + per-row state | `data/store.sqlite` |
| Crop generation, EXIF strip, JPEG re-encode | PIL on CPU |
| Form payload assembly | pure Python, no network |
| Browser dry-fill (Playwright) | Local Chromium |
| Map + gallery rendering | Local HTML files (`demo/map.html`, `data/queue_gallery.html`) |

The vision pipeline never uploads images for inference. The model weights
get downloaded once from HuggingFace and cached at
`~/.cache/huggingface/`. After that, every inference runs offline.

---

## What does leave the machine, and why

| Outbound | Purpose | Payload |
|---|---|---|
| `graph.mapillary.com/images` | image search by bbox | your MLY token, bbox coordinates |
| `graph.mapillary.com/<image_id>` | per-image metadata lookup | your token, image_id |
| Mapillary CDN | thumbnail downloads | one HTTP GET per image |
| `huggingface.co` (Hub API + LFS) | model weight pulls | HF token, one-time per model |
| `bezpiecznie.um.krakow.pl/server/rest/.../FeatureServer` | district / building / parcel lookups | lat,lng (no auth) |
| `msip.um.krakow.pl/arcgis/rest/.../Lokalizator_Krakow/GeocodeServer` | reverse-geocode | lat,lng (no auth) |
| `sheets.googleapis.com` (via `gws`) | optional Sheet export | OAuth via your `gws` install, payload = the queue table |
| `nominatim.openstreetmap.org` | (only when probed manually for control comparisons) | lat,lng, our User-Agent |
| OpenStreetMap / CARTO tile servers | rendered in your browser when viewing `demo/map.html` | standard tile requests, no detection data |
| `unpkg.com` | Leaflet + Leaflet.heat scripts in `demo/map.html` | SRI-pinned, browser-side, no project data |

## Submissions to the city — the only place project data goes live

This is the intentional outbound. `submit --live --confirm-token=WYSLIJ`
is the only command that POSTs report payloads to:

```
https://bezpiecznie.um.krakow.pl/server/rest/services/Graffitti_v1_2/FeatureServer/0/addFeatures
https://bezpiecznie.um.krakow.pl/server/rest/services/Graffitti_v1_2/FeatureServer/0/<oid>/addAttachment
```

Sent: the geometry (lat/lng + Mercator), category enum, severity, the
crop JPEG (EXIF stripped), no email, no name. Server-side `created_user`
column comes back empty for anonymous adds.

To date: **one** test record submitted (objectid 15232) at Vistula river
coordinates to validate the wire format. We closed it immediately via
`updateFeatures` with an explanatory note in Polish. No other submissions
have been made — the queue holds 179+ form-ready entries that will only
go out if explicitly authorised.

## What the city sees if you submit

| Field | Value |
|---|---|
| timestamp | request time |
| source IP | your real IP (we don't proxy) |
| user-agent | random pick from a small allowlist of real browser strings |
| `Accept-Language` | `pl-PL,pl;q=0.9,en;q=0.7` |
| `Origin` / `Referer` | `survey123.arcgis.com` (so it looks webform-shaped) |
| `created_user` | empty (anonymous adds) |
| `adres_mailowy` | null (we never fill it) |
| photo EXIF | stripped, re-encoded |

If you want to obscure the source IP too (the form runs over public
internet from your machine), add an `httpx` proxy in `submit.py` to route
through Tor or a VPN. Current default is plain HTTPS from your local box.

## Storage on disk (paths inside the project)

| Path | What | Lifetime |
|---|---|---|
| `data/store.sqlite` | queue + dedup state | persists across runs |
| `data/images/` | Mapillary thumbnail cache | persists, reusable |
| `data/images/crops/` | detection crops | persists |
| `data/runs/<ts>/proposed.jsonl` | per-run mock payloads | persists |
| `data/runs/<ts>/submissions.jsonl` | per-run actual submission log | persists |
| `data/runs/browser_fill/` | Playwright dry-fill screenshots | persists |
| `data/queue_viz/` | per-source-image overlay JPEGs | persists |
| `demo/map.html` | the interactive map | regenerated by `build_map.py` |
| `.env` | API tokens | gitignored, never committed |
| `~/.cache/huggingface/` | model weights | shared across HF projects |

`.gitignore` keeps `.env`, model weights, image cache, store, and run
logs out of git.

## How to verify

```bash
# 1. The pipeline calls only the endpoints listed above. Trace it:
sudo tcpdump -i en0 -w trace.pcap port 443 &
uv run krakow-clean walk --route karmelicka --max-images 5
# inspect trace.pcap for hosts hit; should be:
#   graph.mapillary.com, images.mapillary.com (CDN),
#   bezpiecznie.um.krakow.pl, msip.um.krakow.pl,
#   huggingface.co (only if weights not cached)

# 2. Vision inference is fully offline once weights are cached.
# Unplug network, run the same walk on cached images:
uv run python scripts/redetect_sam3_clip.py
# This succeeds offline. Mapillary lookups would fail; detector runs fine.
```
